# How Much Temporal History Does a PPO Agent Need?
### A Frame-Stacking Ablation Study on Atari

Code for a Machine Vision course report studying how the number of **stacked frames**
affects a PPO agent on Atari games. A single frame shows object *positions* but not
*motion*; frame stacking restores motion information but the standard value of 4 is
rarely questioned. This project ablates `FRAME_STACK ∈ {1, 2, 4, 8, 16}` on three
games of contrasting dynamics.

## Research questions
- **RQ1:** How many stacked frames does a PPO agent need to learn effectively?
- **RQ2:** Does this number depend on the game's dynamics (fast vs. slow motion)?

## Experimental setup
- **Algorithm:** PPO (Actor–Critic, GAE, clipped objective), adapted from the course
  baseline. Only the environment/preprocessing was changed (VizDoom → Atari).
- **Games:** Breakout (fast ball), Space Invaders (slow, predictable), Pong (fast ball,
  slow to learn).
- **Grid:** 5 frame settings × 3 games × 3 seeds = **45 runs**, 2M steps each.
- **Preprocessing:** grayscale, 84×84, frame skip 4, sign reward clipping.

## Repository structure
| Path | Purpose |
|------|---------|
| `train_ppo.ipynb` | Trains all 45 configurations in series, with resume support |
| `analysis.ipynb`  | All analysis and figures: learning curves, final-reward table, AUC, sample efficiency, stability, cost and Pareto analysis, bootstrap confidence intervals and permutation tests, and saliency maps |
| `results/`        | Per-run training logs (`ppo_history_*.csv`) |
| `models/`         | Saved networks (`ppo_*.pt`), used by the saliency section of `analysis.ipynb` |
| `figures/`        | Figures generated by `analysis.ipynb` |

## How to run
1. Install dependencies:
   ```
   pip install "gymnasium[atari]" ale-py torch pandas matplotlib scipy
   ```
2. Run `train_ppo.ipynb`. It loops over all configurations and writes one CSV (and one
   model checkpoint) per run to the working directory. Finished runs are skipped on
   re-run, so an interrupted session can be resumed by running the loop cell again.
   Training was done on a single NVIDIA T4 GPU (free tier); each run takes ~1 hour.
3. Run `analysis.ipynb` on the resulting CSVs to reproduce the figures and tables in the
   report. It needs no GPU. By default it reads from `results/` and `models/` and writes
   figures to `figures/`; edit the three paths in the first (configuration) cell if your
   files live elsewhere.

## Notes
- Atari training is **CPU-bound** (the environment simulation, not the network, is the
  bottleneck), so runs were executed sequentially on one GPU rather than in parallel.
- A reward-scaling constant inherited from the VizDoom baseline initially prevented
  learning; it was replaced with standard Atari sign-based reward clipping.
